Build a working proof-of-concept web application called **Tumbler Ridge Community Calendar**.

**Purpose:** Consolidate community events and announcements from multiple sources into one simple, searchable, mobile-friendly website for residents of Tumbler Ridge, British Columbia.

### Core features
1. Interactive calendar with month, week and upcoming-list views.
2. Search by event name, description, date, location and keywords.
3. Category filters for Community Events, Families & Youth, Sports & Recreation, Seniors & Services, and Community Notices.
4. Individual event pages with date, time, location, description, source URL and last-verified date.
5. Clean print layout for a weekly schedule.
6. Shareable event URLs.
7. An admin page to create, edit, approve, cancel and remove listings.
8. A submission form accepting event details, website URLs and flyer or screenshot uploads.
9. Design the ingestion architecture so AI can extract structured event details from uploaded images and text later. Never publish uncertain extracted details automatically.
10. Store events in a persistent database. Include duplicate detection support and retain original source information.

### Initial data sources
Prepare the application for importing public information from:
- https://www.districtoftumblerridge.ca/
- https://www.visittumblerridge.ca/community-centre
- https://app.univerusrec.com/tumblerridgepub/facilities/index.asp

Inspect the available public pages and feeds before implementing imports. Do not pretend that data is automatically synchronized if it is not.

### Technical requirements
- Use a simple, maintainable web architecture supported by Replit.
- Use Replit's built-in database if appropriate.
- Make the site fast and easy to use on mobile phones and slow connections.
- No account required to browse events.
- Protect administrative functions and uploads.
- Do not implement Facebook login, private-group scraping, SMS alerts or paid AI integrations in this first iteration.
- Include realistic sample events clearly labelled as demonstration data.
- Provide a README explaining the architecture, setup, data sources, limitations and next steps.

### Build instructions
Start by creating the working application, not merely a plan or mockup. Prioritize the functioning calendar, database, search, filters, print view and admin interface. Test the main user flows, fix errors, and report which features actually work and which remain incomplete. Avoid unnecessary complexity and paid services.
