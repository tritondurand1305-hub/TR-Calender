# UI/UX DESIGN BRIEF — TUMBLER RIDGE COMMUNITY HUB

## 1. Design vision

Design a polished, welcoming, visually impressive community website for Tumbler Ridge, British Columbia.

The website should feel like a permanent, trusted local community service — something the District, local businesses, families, seniors, and community organizations would be proud to share.

**The design concept is “small-town warmth meets premium editorial design.”**

Do not build a generic SaaS dashboard, a standard Google Calendar clone, a flashy startup landing page, or a complicated social network.

The website should have a memorable visual identity rooted in Tumbler Ridge's mountain landscape. It should feel professionally designed without feeling expensive, corporate, intimidating, or over-engineered.

The experience must work especially well for older adults and people who are not confident with technology.

## 2. Use an existing template intelligently

Before building the UI from scratch:

1. Inspect available Replit templates and existing project components.
2. Look for a clean editorial website, local community portal, event-discovery website, or modern civic website template.
3. Choose a template with good typography, accessible navigation, responsive layouts, and straightforward components.
4. Customize it substantially to match this brief rather than accepting the template's default branding.
5. Reuse existing working components and preserve the application's existing backend, database, event functionality, and submission workflows.

Do not waste time installing a large UI framework if the current stack already supports the design.

## 3. Visual identity

### Colour palette

Use a restrained palette inspired by the surrounding mountains and forests:

- **Deep forest green:** `#183D35` — primary brand colour, header accents, buttons.
- **Warm ivory:** `#F7F5EF` — primary page background.
- **Evergreen charcoal:** `#24332F` — main text and headings.
- **Muted sage:** `#DCE6DC` — subtle category backgrounds and secondary elements.
- **Mountain stone:** `#E8E5DD` — borders, dividers, neutral surfaces.
- **Warm ochre:** `#B98745` — occasional highlights and small decorative accents.

Use white where it improves card readability. Maintain accessible text contrast.

Avoid excessive bright colours, neon gradients, dark-mode-first styling, glassmorphism, and colourful dashboard cards.

### Typography

Use a distinctive but highly readable heading font paired with a clean sans-serif body font.

Suggested pairing:
- Headings: DM Serif Display or a similar restrained editorial serif.
- Body and interface: Inter, Source Sans 3, or a similar highly legible sans-serif.

Use large, clear headings and comfortable body text. Body copy should generally be at least 16px on desktop, with important buttons and mobile controls comfortably sized.

Avoid tiny labels, overly thin fonts, all-caps paragraphs, and excessive font variations.

### Photography and branding

The hero image is the website's signature visual element.

Use one excellent, wide landscape photograph of Tumbler Ridge and the surrounding mountains, evergreen forests, or distinctive local scenery. Ideally, use a genuine photograph supplied by the site owner or an image that is properly licensed for use.

Do not use a generic stock photo of an unrelated mountain town.

The image should be cinematic but natural: soft morning or evening light, rich forest greens, mountain detail, and a welcoming atmosphere.

Apply a subtle dark gradient behind the hero text only when needed for contrast. Do not put text over a visually busy part of the photograph.

If a suitable photograph is not available, create an attractive layout that can accept one later. Do not make the website depend on an unreliable external image URL.

## 4. Homepage layout

Build the homepage in this order.

### A. Simple, elegant navigation

Create a clean header with the following brand:

**TUMBLER RIDGE**
*COMMUNITY HUB*

Keep the branding compact, distinctive, and readable.

Navigation links:
- Calendar
- Community Notices
- Submit an Event

Add a clear, understated button on the right: **Get Email Updates**.

On mobile, use a simple menu button with clearly labelled navigation. Avoid complicated mega-menus, excessive navigation links, or multiple competing calls to action.

The header should feel polished and trustworthy, not like an administrative control panel.

### B. Cinematic hero section

Use a wide, high-quality landscape image with generous height on desktop and a thoughtfully cropped version on mobile.

Headline:

**Good things are happening here.**

Supporting text:

“Your local guide to events, programs and community news in Tumbler Ridge.”

Primary button:

**Explore Upcoming Events**

Optional small secondary link:

“Have something to share? Submit an event.”

The headline should be prominent without dominating the entire screen. The hero should establish an immediate emotional connection to the town.

Do not add carousels, rotating banners, animated text, autoplay video, or multiple competing buttons.

### C. Upcoming events — the main attraction

Immediately below the hero, transition into a warm ivory background.

Heading:

**What's happening in Tumbler Ridge**

Supporting text:

“Find something to do, discover local programs, and see what's coming up.”

Make the next available events visible without requiring visitors to create an account or navigate through several screens.

Provide a small set of clear category filters:

- All Events
- Families & Youth
- Sports & Recreation
- Community Notices

Use simple pill-shaped filters with a clear selected state. These are optional shortcuts, not a complicated filter panel.

Display events in clean, readable cards or a structured list. Each event should clearly show:

- Date and day of the week.
- Event title.
- Start time, when known.
- Venue or location, when known.
- A small category label.
- A clear way to open the full event details.

Make the date easy to spot. A visitor should be able to scan the page quickly and understand what is happening and when.

Use realistic demonstration events only if real events are unavailable, and label them clearly as sample content. Never present invented events as genuine community announcements.

### D. A useful “This week” overview

Beside the upcoming-events list on desktop, include a compact weekly overview.

Show the current week, days of the week, and an indication of days with events. Selecting a day should filter the upcoming-events list.

Keep this component simple. It is a visual shortcut, not a full spreadsheet-style calendar.

On mobile, stack this section below the upcoming-events list or collapse it into a simple, accessible weekly selector.

Do not let the weekly overview compete visually with the event list.

### E. A clear full-calendar entry point

Include a visible button:

**View Full Calendar**

The full calendar should support:
- Month view.
- Week view.
- Upcoming-list view.

Make the upcoming-list view the default on smaller screens. Month and week views should be available without overwhelming the visitor.

Provide obvious previous and next controls, a clearly labelled current date range, and a **Today** button.

Do not force visitors to learn drag-and-drop, complex calendar controls, or unfamiliar gestures.

### F. Community notices

Create a separate section for important everyday community information that is not necessarily an event.

Examples might include facility notices, community-service announcements, program registration reminders, or local organization updates.

Keep ordinary community notices visually distinct from scheduled events.

Do not imitate official emergency-alert systems or present unverified notices as official government announcements.

### G. Submit an event

Create a welcoming, understated section near the bottom of the homepage.

Headline:

**Helping the community stay connected starts with you.**

Supporting text:

“Organizing an event, running a program, or sharing a community announcement? Send it in and help everyone stay informed.”

Button:

**Submit an Event**

The submission process should remain straightforward. Visitors must not need an account.

Allow submissions using event details, copied text, a source URL, or an uploaded poster or screenshot, according to the existing application's functionality.

Make it clear that submitted information may need to be reviewed before publication.

### H. Optional email updates

Add a compact, attractive subscription section that feels like a useful community service rather than an advertising campaign.

Headline:

**Stay in the loop.**

Supporting text:

“Get a simple weekly roundup of what's happening around Tumbler Ridge, delivered to your inbox.”

Primary action:

**Get Email Updates**

Explain that subscribing is optional and that people can unsubscribe at any time.

Use the existing email-subscription implementation, including confirmation, consent, preference management, secure storage, and unsubscribe support. Do not invent a separate signup system or bypass its consent requirements.

Keep the subscription form short and easy to understand.

### I. Footer

Use a deep forest-green footer with a restrained layout.

Include:
- Tumbler Ridge Community Hub branding.
- Calendar.
- Community Notices.
- Submit an Event.
- Email Updates.
- Contact information, if configured.
- Privacy Policy.
- A discreet note explaining that event information may originate from community organizations and should be checked with the organizer when details change.

Do not imply that the website is an official District of Tumbler Ridge service unless the District has formally authorized that representation.

## 5. Event detail pages

Event detail pages should be clean, shareable, and useful when opened directly from a text message, email, or Facebook post.

Display:
- Event title.
- Date and time.
- Location.
- Description.
- Cost or registration details, when available.
- Organizer/contact information, when available.
- Original source link.
- Last-verified date, where available.
- A prominent **Share Event** action.
- A print-friendly layout.

Missing details should be labelled as unavailable rather than invented.

Do not require login to view or share an event.

## 6. Accessibility and ease of use

The website should be comfortable for older residents and people using slower connections or smaller screens.

Requirements:
- Clear text with strong contrast.
- Large clickable controls.
- Familiar words instead of technical terminology.
- Simple navigation and consistent button placement.
- Visible keyboard focus.
- Semantic headings and accessible form labels.
- Properly labelled controls for screen readers.
- Useful error messages that explain how to fix a problem.
- No hover-only essential information.
- No auto-playing media or distracting animations.
- Respect reduced-motion preferences.
- Optimized, responsive images and minimal unnecessary JavaScript.

Never communicate important event information through colour alone.

Keep each page focused on one primary task. Avoid displaying every possible feature at once.

## 7. Responsive design

Design and test three layouts:

**Desktop:** A cinematic hero, generous whitespace, upcoming events beside the weekly overview, and a clear visual hierarchy.

**Tablet:** A more compact hero and simplified two-column layout where space permits.

**Mobile:** A compact header, appropriately cropped hero image, stacked event cards, large touch targets, and the next upcoming events visible quickly.

Do not simply shrink the desktop design. Make deliberate layout choices for each screen size.

## 8. Subtle details that make the site feel professionally designed

Use:
- Consistent spacing and alignment.
- Thin, understated dividers.
- Restrained corner rounding.
- Subtle transitions for hover and focus states.
- Small, consistent date treatments.
- High-quality empty states when no events match a filter.
- Helpful messages when no events are scheduled.
- Thoughtful loading and error states.
- Print styles that remove navigation and unnecessary decoration.

Avoid:
- Excessive shadows.
- Every section being placed inside a separate rounded rectangle.
- Generic emoji as the main icon system.
- Excessive badges and decorative labels.
- Huge blank spaces between useful information.
- Fake ratings, popularity counts, or fabricated social proof.
- Fake live indicators.
- Unnecessary login prompts.
- Popups that interrupt browsing.

## 9. Technical and implementation requirements

Treat this as a visual and usability improvement to the existing community calendar, not a rewrite.

Before making changes:
1. Inspect the existing project structure, framework, components, and routing.
2. Identify which calendar, submission, database, and subscription features already work.
3. Reuse existing components and data.
4. Preserve all existing functionality and working routes.
5. Make the design responsive without adding unnecessary dependencies.

The website must remain functional, not just attractive. Filters must actually filter events, navigation must work, event links must resolve, and forms must connect to their real backend workflows.

Do not replace working functionality with mockups or static sample data.

## 10. Final quality target

The finished website should look like a thoughtfully commissioned local community publication: recognizable, welcoming, modern, and specific to Tumbler Ridge.

A resident should immediately understand three things:

1. This is a place to find out what's happening locally.
2. Finding an event is easy.
3. Sharing an event or getting updates is optional and straightforward.

Prioritize visual identity, readability, trust, and simplicity over feature density.

Build the actual interface, run the application, test the main user flows on desktop and mobile sizes, and fix obvious visual or functional problems before declaring the work complete.
